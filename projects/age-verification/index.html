Privacy-Preserving AI Age Assurance

A production-oriented Azure landing zone for bring-your-own age-estimation models where the verification image is encrypted before upload, remains ciphertext through the public edge, is decrypted only inside isolated inference memory, and is never intentionally retained.

ARCHITECTURE PROBLEM

Verify an age signal without turning the image into a platform asset.

The architecture treats the image as highly sensitive transient input rather than application data. Application-layer envelope encryption protects it beyond TLS, the public gateway never needs the plaintext, and the inference boundary is deliberately narrow so the model receives only what it must process.

PRIVACY CONTRACT

Security controls are part of the data lifecycle.

◇

Encrypted before upload

The client generates a one-time symmetric key, encrypts the re-encoded frame with AES-256-GCM, and wraps that session key for the inference boundary. TLS remains an additional transport layer.

▦

Private inference boundary

Front Door reaches a private Container Apps environment over Private Link. The gateway handles request policy and routing without decrypting the photograph; only the inference process can unwrap the session key.

▤

No intentional image retention

No verification-image datastore is provisioned. The design prohibits plaintext, ciphertext, embeddings, tensors, raw age estimates, and session keys from application logs or persistent storage.

KEY DECISIONS

Reduce trust instead of asking every layer to be trusted.

Application-layer encryption beyond TLS

TLS protects transport, but the architecture also keeps the image encrypted through the edge and gateway so those components do not need access to the underlying photograph.

No image storage service

The safest retention policy for this use case is architectural omission: there is no image database, blob container, or queue intended to persist verification imagery.

Short-lived anti-replay state only

Azure Managed Redis holds opaque session and nonce state with short TTLs. It is not used to store images, biometric material, or raw model outputs.

Bring-your-own model boundary

The platform defines the inference contract and isolation boundary without claiming that an arbitrary customer model is fair, compliant, non-exfiltrating, or suitable for a particular jurisdiction.

Cloud validated
The dev foundation passes live Azure control-plane preflight through secretless OIDC.

Foundation and workload Bicep lint/build cleanly and all dev, test, and production parameter files compile. The live dev foundation What-If resolves 24 planned resources; two managed-identity-dependent RBAC assignments remain intentionally unsupported by What-If until deployment-time principal IDs exist. The dev preflight omits Managed Redis because live B0/B1 capacity was unavailable for this subscription, while Redis remains part of the production architecture and compiler-validated profiles. No resources were deployed.

Project scope: this is an architecture, contract, and Infrastructure-as-Code package. No production age-estimation model is bundled, and the current source does not claim to provide a complete reference gateway/inference implementation. Legal compliance, model fairness, and customer-model behavior remain customer responsibilities.
