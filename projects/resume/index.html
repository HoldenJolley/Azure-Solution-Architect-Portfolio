REQUIREMENTS & CONSTRAINTS

Do not pay for services the workload does not need.

The workload is HTML, CSS, JavaScript, and a resume PDF. It needs HTTPS, a custom domain, global static delivery, repeatable deployment, pull-request previews, and a recovery path—but it does not need server compute, a database, a paid CDN, or a distributed tracing platform.

The architecture therefore optimizes for minimum operational and financial surface area while keeping an explicit upgrade path for future requirements rather than pre-provisioning enterprise services for résumé value.

DELIVERY & SECURITY

Deployment is automated without storing a reusable Azure client secret.

GitHub Actions authenticates to Azure through workload identity federation using OIDC. Infrastructure is modeled in subscription-scoped Bicep, compiler-validated in CI, and evaluated with live ARM What-If before any production deployment is allowed.

The site artifact is curated so public content is separated from IaC and internal documentation. Security headers and Content Security Policy are part of the static-site configuration, while production deployment remains an explicit manual action rather than something a normal push can trigger.

COST MODEL

The baseline spends only where a requirement exists.

Static hosting

Azure Static Web Apps Free: expected Azure hosting charge is $0 while the site remains within the Free-plan quota.

Global delivery + TLS

Included with Static Web Apps Free, so there is no separate Front Door/CDN or certificate service in the baseline.

DNS

The existing external registrar/DNS provider maps the custom domain. This avoids adding Azure DNS solely for the portfolio.

CI/CD

GitHub Actions handles automation. Any GitHub usage cost is separate from Azure hosting cost and depends on the account's GitHub quotas.

Backend compute + database

None. Static content does not justify a runtime or persistence layer, so both remain $0 by architectural omission.

Azure monitoring workspace

None in the baseline. A static personal portfolio does not currently justify dedicated Application Insights / Log Analytics resources.

FREE-PLAN GUARDRAILS

Free is a constraint, not an excuse to hide limits.

01Capacity

The architecture was written around the Free-plan included quotas for bandwidth, environment storage, preview environments, and custom domains. If real usage approaches those boundaries, the correct response is a deliberate upgrade—not wishful thinking.

02Availability

The Free tier does not provide an SLA. That is accepted for a personal portfolio and is explicitly not presented as an enterprise availability posture.

03Advanced controls

Private endpoints, IP restrictions, paid support/availability, and other advanced requirements are future triggers for Standard or a different architecture rather than baseline features.

OPERATIONS & RECOVERY

A stateless site should have a stateless recovery model.

Bad content release

Git is the source of truth. Revert the content change and redeploy rather than restoring mutable application state.

Infrastructure drift or accidental removal

Recreate the intended resource group and Static Web App from Bicep, then republish the curated static artifact.

DNS issue

The custom-domain mapping lives with the external DNS provider, so DNS troubleshooting is intentionally separated from the Azure hosting footprint.

Platform outage

The Free-tier baseline accepts the lack of an SLA. If availability becomes business-critical, that requirement itself triggers a paid architecture decision.

KEY DECISIONS

Cost optimization is requirement-driven architecture.

Static Web Apps instead of App Service

The workload is static. Paying for an App Service plan would add compute cost and operational surface without adding a current capability.

External DNS instead of Azure DNS

The existing provider can map the domain to Static Web Apps, so Azure DNS would create a recurring resource without solving a new requirement.

No dedicated observability stack

The site has no backend transaction or dependency graph that justifies distributed tracing. Deployment history and basic resource health are sufficient for the current workload.

Upgrade only on a real trigger

Bandwidth, domain count, preview capacity, SLA, private networking, IP restrictions, backend API requirements, or business criticality are the conditions that justify a larger architecture.

GitHub Actions authenticates through secretless OIDC and a live subscription-scope Resource Manager What-If resolves the design to one resource group and one Free-tier Static Web App. That is control-plane evidence only; runtime HTTPS, custom-domain, preview-environment, performance, and recovery behavior still require deployment. Actual production deployment remains gated and has not been run.

Current boundary: the Free tier is intentionally right-sized for a personal portfolio and is not an enterprise SLA claim. Domain registration is an external cost, and the design will only grow when a real requirement—availability, networking, traffic, backend functionality, or business criticality—earns the additional Azure services.
