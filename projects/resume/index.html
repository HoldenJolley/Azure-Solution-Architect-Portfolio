ARCHITECTURE PROBLEM

Do not pay for services the workload does not need.

A static resume and portfolio does not require always-on compute, a database, a paid CDN, or a monitoring workspace. The architecture deliberately minimizes the Azure footprint while retaining HTTPS, custom-domain support, pull-request previews, repeatable Infrastructure as Code, CI/CD, and a documented path to a paid tier if requirements change.

COST DESIGN

Use less Azure on purpose.

Static Web Apps FreeRight-sized hosting for a static personal portfolio with global static delivery, managed HTTPS, custom domains, and preview environments.
No server computeNo App Service plan, VM, Functions backend, or always-on application runtime because the site has no server-side compute requirement.
No paid edge layerNo Front Door or separate paid CDN because Static Web Apps already satisfies the static content distribution requirement.
No unnecessary stateNo database, storage account, or dedicated observability workspace. Source control is the recovery mechanism for a stateless site.
KEY DECISIONS

Cost optimization is requirement-driven architecture.

Static Web Apps instead of App Service

The workload is HTML, CSS, JavaScript, and a resume PDF. Paying for an App Service plan would add compute and operational surface without adding value.

External DNS instead of Azure DNS

The existing domain provider can map the custom domain, avoiding another recurring Azure resource solely for portfolio DNS hosting.

No dedicated observability stack

A static personal site has no backend transaction or dependency graph that justifies Application Insights and Log Analytics in the baseline architecture.

Upgrade only on a real trigger

Bandwidth, domain count, preview capacity, private networking, or SLA requirements are explicit signals for moving beyond the Free architecture.

Cloud validated
The intended Free-tier footprint has been evaluated against Azure without creating resources.

Bicep lint/build and production parameters are green. GitHub Actions authenticates through secretless OIDC and a live subscription-scope Resource Manager What-If resolves the design to one resource group and one Free-tier Static Web App. Actual deployment remains gated and has not been run.

Tradeoff: the Free tier is appropriate for a personal portfolio, not a claim of enterprise availability. The architecture documents when the site should move to a paid tier instead of disguising Free-tier limitations.
